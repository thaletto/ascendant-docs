# Issue Tracker: Linear

Issues and specs for this repo live in Linear.

## Conventions

- Treat Linear as the authoritative source for engineering work.
- Before planning or implementing, read the complete issue description, comments,
  blocking and related relationships, and linked resources.
- Preserve issue metadata, relationships, and context unless the requested work
  explicitly replaces them.
- Use native Linear relationships for blocking and related work.
- Keep pull requests out of the triage queue; triage concerns Linear issues.

## When a skill says “publish to the issue tracker”

Create or update the corresponding Linear issue with the complete problem,
scope, acceptance criteria, and relevant links.

## When a skill says “fetch the relevant ticket”

Read the Linear issue, its comments, relationships, linked resources, and current
status before making recommendations or changes.

## Triage

Use the labels documented in `docs/agents/triage-labels.md`. A ticket is ready
for agent work only when its context and acceptance criteria are complete.
